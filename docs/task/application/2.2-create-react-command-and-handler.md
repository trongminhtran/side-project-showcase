## Design Constraints
- Application enforces:
  - Project existence
  - Project visibility (must be Public)
  - One reaction per user per project
- Domain Reaction is immutable

## Required Behavior
### ReactProjectCommand
- Properties:
  - ProjectId (Guid)
  - UserId (Guid)
  - Type (ReactionType)

### Handler Responsibilities
1. Load project by ProjectId
2. Reject if project not found
3. Reject if project is Private
4. Check existing reaction by (ProjectId, UserId)
5. If exists → remove old reaction
6. Create new Reaction aggregate
7. Persist reaction
8. Return updated reaction counts (Like/Dislike/Love)

## Repository Contracts
### IProjectRepository
- GetById(Guid projectId)

### IReactionRepository
- GetByProjectAndUser(Guid projectId, Guid userId)
- Add(Reaction reaction)
- Remove(Reaction reaction)
- CountByProject(Guid projectId)

## Forbidden
- Toggle or switch logic inside Domain
- Domain validation of project visibility
- EF Core references
